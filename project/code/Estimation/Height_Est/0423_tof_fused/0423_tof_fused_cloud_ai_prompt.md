# 四 TOF 高度融合离线研究提示词

你现在扮演一名飞控高度估计与传感器融合工程师。你的任务不是空谈新算法，而是先基于我提供给你的现有代码和飞行日志，严格离线复现当前双 TOF 融合算法，再从复现结果中定位漏洞，最后给出 2 到 4 个可落地的四 TOF 融合候选方案，并说明为什么推荐或不推荐它们。

## 你的核心目标

1. 先严格复现当前 `Height_Est.c` 的双 TOF 离线回放，确认能从日志中重建当前算法的关键中间量，并与日志输出保持一致。
2. 复现不是为了形式，而是为了看清当前算法在哪些场景下有漏洞，尤其是：
   - 只用 `TOF1 + TOF4` 是否丢失了 `TOF2/TOF3` 的有效信息。
   - 单路或多路被供电线缆遮挡时，当前算法是否容易被带偏。
   - 当前残差门控和 AB 更新是否会把错误高度注入成错误速度。
   - 当前输出是否真的适合高度闭环和速度闭环。
3. 在此基础上研究如何把 `TOF2 + TOF3` 也纳入融合，争取得到更平滑、更鲁棒、更适合闭环控制的高度和竖直速度。
4. 最后给出 2 到 4 个四 TOF 融合候选方案，每个方案都必须包含公式、输入输出、异常路处理逻辑、优缺点、实现风险、离线评估口径和伪代码。

## 现有代码的关键事实

你会同时拿到 `Height_Est.c`、`Height_Est.h` 和飞行日志 CSV。请按以下逻辑理解当前算法。

### 1. 当前四路 TOF 的姿态解耦

四路 TOF 都先做姿态解耦，公式为：

`h_i = d_i * cos(pitch) * cos(roll) + s_pitch_i * A * sin(pitch) + s_roll_i * B * sin(roll) * cos(pitch)`

当前固定参数为：

- `A = 65.40 mm`
- `B = 84.81 mm`
- `pitch_sign = {+1, -1, +1, -1}`
- `roll_sign = {+1, +1, -1, -1}`

四路编号与物理位置固定为：

- `TOF1 = 后右`
- `TOF2 = 前右`
- `TOF3 = 后左`
- `TOF4 = 前左`

### 2. 当前每路 TOF 的本地预处理

每路姿态解耦后的高度还会经过：

- 中值滤波，窗口 `3`
- 阶跃限幅，限幅 `30 mm`
- 最终 clamp 到 `[0, 1300]`

日志里的 `log_tof1_height_mm..log_tof4_height_mm` 已经是解耦后、滤波后、限幅后、clamp 后的高度，不是原始斜距。

### 3. 当前融合器只使用 TOF1 和 TOF4

虽然四路都有解耦后的高度，但当前融合器只使用：

- `TOF1`
- `TOF4`

`TOF2` 和 `TOF3` 当前仅记录到日志，不参与融合。

### 4. 当前双 TOF 融合器的结构

当前是一个 AB 型高度-速度估计器。

- 状态：
  - `s_height_est_mm`
  - `s_height_est_vz_mps`
- 固定周期：
  - `dt = 0.01 s`
- 预测：
  - `h_pred = clamp(h + vz * dt * 1000)`
- 残差门限：
  - `120 mm`
- 残差权重：
  - 无效路权重 `0`
  - 若 `|residual| >= 120`，权重 `0`
  - 否则 `q = 1 - |residual| / 120`
- 初始化阶段：
  - 若估计器尚未 ready，则直接对当前有效量测做简单平均初始化
- 正常阶段：
  - 用 `TOF1` 和 `TOF4` 的残差权重做加权平均，得到 `z_meas`
- AB 更新参数：
  - `alpha = 0.18`
  - `beta = 0.03`
- 更新公式：
  - `h = clamp(h_pred + alpha * residual)`
  - `vz = v_pred + (beta / dt) * (residual * 0.001)`
- 纯预测保持：
  - 当无有效量测时，最多允许 `15` 帧 predict-only
  - `vz` 衰减系数 `0.95`
- 硬重锁：
  - 当权重全失效，但 TOF1 或 TOF4 里仍有有效量测，且持续 predict-only 达到 `15` 帧时，允许直接平均重锁

## 日志切段与脏数据处理要求

这份日志不是一段连续的单调时间序列，必须先清洗，再切段，再分析。

### 1. 先剔除非有限值脏行

日志中存在一行脏记录，形式类似：

`nan,nan,nan,nan,0,0,0,0,-0.802481,685.501221`

这行必须在分析前直接剔除，不能参与时间切段，也不能参与回放。

### 2. 剔除该脏行后，再按时间戳回跳切成 4 段

剔除 `nan` 行后，会观察到 3 次时间回跳，因此应该切成 4 个单调时间段：

- `Segment 0`: `33098..73573 ms`
- `Segment 1`: `7101..12680 ms`
- `Segment 2`: `7601..12480 ms`
- `Segment 3`: `8501..228356 ms`

默认假设：

- 这 4 段应被当作 4 次独立日志会话
- 每段离线回放时，都从与 `HeightEst_ResetAll()` 一致的初始状态开始

### 3. 允许尾段剔除，但规则必须明确

需要注意：

- 这份日志包含多次飞行
- 飞行中存在炸机或尾段脏数据
- 供电线缆可能遮挡 TOF，造成单路或多路高度突变

因此：

- 允许对每段明显炸机或明显失控的尾段做剔除
- 但必须明确说明剔除规则，不能凭感觉删
- 必须同时保留一份“不剔尾”的基线结果，用于和“剔尾后”结果对比

### 第三部分：提出 2 到 4 个四 TOF 融合候选方案

- 对脏尾段剔除前后的稳定性
- 相比当前双 TOF 基线的收益和代价
