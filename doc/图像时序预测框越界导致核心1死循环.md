# 图像时序预测框越界导致核心1死循环

## 问题现象

飞机飞行一段时间后，核心1停止更新，随后出现以下连锁现象：

- 前后摄和下摄图像数据停止刷新。
- 车端进入核心1或2BL3参数菜单时，参数修改失败并逐渐显示为`N/A`。
- 参数存档读取失败。
- 核心0仍可运行，核心0本地参数仍可调节。
- 临时阶段诊断停在`S12`，即下摄时序车灯接管阶段，循环心跳不再增长且没有Fault记录。

这些现象容易被误判为Camera SPI、IPC或2BL3通信故障。实际原因是核心1卡在图像算法的永久循环中，导致依赖核心1的图像、SPI和参数事务同时停止。

## 根因

车灯短暂丢失时，时序跟踪会根据位置和速度生成下一帧预测框。预测框完全移出图像左侧或上侧后，边界可能出现：

```c
min_x = 0;
max_x = -1;
```

旧代码将动态边界转换为`unsigned char`并使用闭区间循环：

```c
unsigned char x;

for(x = (unsigned char)min_x; x <= (unsigned char)max_x; x++)
{
    /* ... */
}
```

`-1`转换为`unsigned char`后变成`255`。当`x`执行到`255`再自增时会回绕到`0`，而`0 <= 255`始终成立，因此核心1永久停在该循环。

该问题只在特定画面、运动速度和丢帧组合下触发，所以上电静止测试通常正常，飞行过程中才会暴露。

## 修复方法

### 1. 浮点值转整数前先验证

预测中心、预测半径和角度必须是有限值，禁止将`NaN`或无穷值转换为整数：

```c
if((isfinite(image_cx) == 0) ||
   (isfinite(image_cy) == 0) ||
   (isfinite(radius) == 0) ||
   (isfinite(track->angle) == 0))
{
    return 0;
}
```

### 2. 完全出画面的预测框立即失效

边界转换和裁剪前，先判断预测框是否与图像没有交集：

```c
if((image_cx + radius < 0.0f) ||
   (image_cy + radius < 0.0f) ||
   (image_cx - radius >= (float)BEACON_IMAGE_W) ||
   (image_cy - radius >= (float)BEACON_IMAGE_H))
{
    return 0;
}
```

### 3. 动态闭区间循环使用`int`

```c
int x;
int y;

for(y = min_y; y <= max_y; y++)
{
    for(x = min_x; x <= max_x; x++)
    {
        /* 访问前保证矩形合法 */
    }
}
```

只有在调用参数明确要求像素坐标类型时，才在边界验证后将单个坐标转换为`unsigned char`。

### 4. 裁剪后检查空窗口

```c
if((max_x < 0) || (max_y < 0) ||
   (min_x >= BEACON_IMAGE_W) || (min_y >= BEACON_IMAGE_H) ||
   (min_x > max_x) || (min_y > max_y))
{
    return 0;
}
```

核心1下摄和两块2BL3共用的图像算法均已按上述规则增加保护。2BL3原循环变量已经是`int`，不会发生相同的255回绕，但仍需要拒绝非有限值和非法预测框。

## 调试方法

遇到“图像、2BL3参数和核心1参数同时失效，但核心0仍正常”的现象时，按以下顺序排查：

1. 判断核心1循环是否继续运行，不要先假设是通信故障。
2. 区分Fault和忙循环：Fault寄存器无记录且循环心跳停止，通常说明代码卡在阻塞等待或永久循环。
3. 临时按主循环阶段增加阶段码，逐步缩小到具体算法函数。
4. 检查该函数内所有动态边界、闭区间循环、浮点转整数和无符号变量。
5. 修复后删除高频阶段写回、耗时统计和扩展遥测，避免调试代码长期占用实时路径。

## 代码审查规则

- 图像宽高和窗口边界使用`int`。
- 不允许将可能为负数的坐标直接转换为无符号类型。
- 所有动态矩形都要执行“生成、判定相交、裁剪、判空”四步。
- 浮点坐标转整数前必须检查`isfinite()`。
- `for(i = min; i <= max; i++)`必须证明`min <= max`且自增不会回绕。
- 跟踪目标离开视野后应失效或重置，不能继续传播非法预测状态。
